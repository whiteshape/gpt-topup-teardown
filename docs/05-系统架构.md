# 05 · 系统架构（代充业务全链）

这不是"一个脚本"，是一条流水线。分层如下，每层职责单一、可单独替换。

```
┌──────────────────────────────────────────────────────────────┐
│ 接入层                                                        │
│   Web 控制台 (GET /)          REST API (/api/v1/*)            │
│   注册/登录/提交/查询          CDK 批发 / 对外开发者 API        │
└───────────────┬──────────────────────────────────────────────┘
                │ bearer token（sha256 存储）
┌───────────────▼──────────────────────────────────────────────┐
│ 业务层                                                        │
│   用户与余额     CDK 生命周期     订单状态机      审计日志      │
│   (users)       (cdks)          (orders)       (audit)       │
└───────────────┬──────────────────────────────────────────────┘
                │ 异步任务（Worker 线程池）
┌───────────────▼──────────────────────────────────────────────┐
│ 协议层（ChatGPT）                                             │
│   Session→Cookie → /me → accounts/check → payments/checkout   │
│   → 轮询激活 → 取消续费                                        │
└───────────────┬──────────────────────────────────────────────┘
                │ 支付路由：cs_live / oaics
┌───────────────▼──────────────────────────────────────────────┐
│ 支付层                                                        │
│   StripeAdapter  (cs_live_, 无浏览器)                         │
│   OaicsAdapter   (oaics_, Playwright，可选中依赖)              │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ 资源层                                                        │
│   卡池 (cards, DPAPI 加密)     BIN 统计 (bin_stats)            │
│   出口代理 (proxy / payment_proxy)                            │
└──────────────────────────────────────────────────────────────┘
```

## 一、模块清单

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `chatgpt.py` | ChatGPT 结账协议 | 唯一的"官方接口知识"都在这 |
| `stripe_pay.py` | Stripe 前端支付 | `init` → `confirm`，无浏览器 |
| `adapters.py` | 支付路由 | `cs_live_` vs `oaics_` 的分叉点 |
| `cards.py` | 卡池调度 | 按 BIN 成功率选卡 |
| `orders.py` | 订单状态机 | 唯一会"扣钱"的地方 |
| `worker.py` | 异步执行 | 有界线程池，不落盘队列 |
| `store.py` | 持久化 | 表结构沿用对方命名 |
| `auth.py` | 账号体系 | PBKDF2 + token 哈希存储 |
| `dpapi.py` | 静态加密 | 卡号/CVC 用 Windows DPAPI |
| `api.py` | HTTP + 控制台 | 同款 `/api/v1` 契约 |
| `cli.py` | 手工分步 | 排障用 |
| `script_gen.py` | 生成 F12 脚本 | 无 Session 场景 |

## 二、数据模型

```
users(id, email, password_hash, is_admin, balance_minor, frozen_minor, invite_code)
tokens(token_hash, user_id, expires_at)          -- 只存哈希
cards(id, user_id, pan_cipher, cvc_enc, ...)     -- DPAPI 密文
cdks(code, user_id, plan, status, order_id)      -- unused/frozen/reserved/consumed/disabled
orders(... stage, purchase_state, funding_state, payment_path, session_enc, bin)
order_events(order_id, stage, level, message, data_json)
bin_stats(bin, plan, attempts, successes, declines, last_error, last_amount, last_seen)
recharges(user_id, amount_minor, method, status) -- 余额流水
audit(user_id, action, detail)
```

`orders.session_enc` 是 DPAPI 密文，**订单结束立刻清空**。

## 三、订单状态机

```
queued
  └─ credential_check ── 失败: account_check_forbidden / gpt_session_*
       └─ pricing ────── 失败: checkout_pricing_unavailable / amount_range
            └─ checkout ─ 失败: gpt_risk_blocked / already_subscribed / store_subscription_processor
                 └─ payment ─ 失败: bank_declined / merchant_blocked / requires_action
                      └─ subscription ── 未翻面: activation_unconfirmed
                           └─ renewal（取消续费）
                                └─ completed
```

状态字段三套并存（和对方一致）：

- `stage`：流程走到哪
- `purchase_state`：`NOT_STARTED / SUBMITTED / PENDING / CONFIRMED / FAILED / UNKNOWN`
- `funding_state`：`NONE / FUNDING_REQUIRED / FUNDED`

**`UNKNOWN` 是刻意保留的**：付款成功但订阅没确认，不能标成功也不能标失败，否则对账会错。

## 四、支付路由（最关键的一处判断）

```python
def route_for(session_id):
    if session_id.startswith("cs_"):    return "cs_live"   # Stripe 会话
    if session_id.startswith("oaics_"): return "oaics"     # OpenAI 托管
    return "unknown"
```

| 路由 | 出现概率 | 支付方式 | 需要浏览器 |
| --- | --- | --- | --- |
| `cs_live` | 约 12% | Stripe `payment_pages/{id}/init` + `/confirm` | ❌ |
| `oaics` | 约 88% | 打开 `chatgpt.com/checkout/...` 填卡 | ✅ Playwright |

`OaicsAdapter` 在未安装 Playwright 时**明确报错** `browser_adapter_unavailable`，
不会假装成功——这是刻意的。

## 五、卡池与 BIN 统计

选卡顺序（`cards.select`）：

1. 操作员显式指定 `card_id`
2. 该套餐下 BIN 成功率最高的卡
3. 没有历史的卡（探索）
4. 其余

连续失败 ≥ 2 次的卡会被跳过（除非只剩它）。每次支付都会写 `bin_stats`：

```
attempts / successes / declines / last_error / last_amount / last_seen / success_rate
```

这就是对方 `/card/openai-payments` 那张表的等价物。**它是你以后定价和排卡的依据。**

## 六、安全设计

| 风险 | 处理 |
| --- | --- |
| 库被拷走 | 卡号/CVC/会话用 DPAPI 加密，绑定当前 Windows 用户 |
| 会话泄露 | `session_enc` 订单结束即清空 |
| 密码泄露 | PBKDF2-HMAC-SHA256 (210k 轮) + 随机盐 |
| token 泄露 | 只存 sha256，不存明文 |
| 越权 | 订单/卡片按 `user_id` 过滤；admin 路由单独校验 |
| 滥用 | 下单必须带 `authorized=true`，落 `audit` 表 |
| 重复扣款 | 订单终态不可重入；`UNKNOWN` 走人工对账 |

**未做（上线前必须补）**：HTTPS、速率限制、CSRF、CSP、日志脱敏、卡号访问审计。

## 八、已知边界

1. **卡源**：代码管卡，不造卡。需要发卡方（BIN sponsor）。
2. **`oaics` 支付**：需要 Playwright（约 150MB）+ 人工过 hCaptcha/3DS。
3. **风控**：单账号连续失败会被临时封，必须账号轮换。
4. **合规**：转售账号权益违反 OpenAI 条款；卡源不明时可能触及拒付与刑责。系统只提供技术能力，不解决授权问题。
