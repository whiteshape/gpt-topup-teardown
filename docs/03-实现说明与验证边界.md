# 03 · 实现说明与验证边界

## 一、这份实现是什么

对 the platform「GPT 直充」链路的**独立复现**：不依赖它的站点，只依赖
① ChatGPT 官方结账接口 ② Stripe 前端支付协议 ③ 你自己的卡。

```
impl/zovo/
  chatgpt.py      协议引擎：Session → Cookie → 校验 → 报价 → 取链 → 等激活 → 取消续费
  stripe_pay.py   支付引擎：取 pk → init → confirm → 处理拒付/3DS
  script_gen.py   生成与官方同款的「F12 取链脚本」（短链/长链）
  store.py        SQLite：users / cards / cdks / orders / order_events
  orders.py       订单状态机（沿用对方 stage / state / error 命名）
  api.py          HTTP 服务，同款 /api/v1 契约（stdlib，无第三方依赖）
  cli.py          手工分步
```

依赖：`requests`（已装）。服务端与网关只用标准库。

## 二、已验证（可重复）

```powershell
cd "./impl"

# 结账请求体与 bundle 中 Pe() 逐字段一致
python -c "from zovo.chatgpt import ChatGptSession as S; import json; print(json.dumps(S.__new__(S).build_checkout_payload('plus','PH','PHP','hosted')))"

# F12 脚本可生成（短链/长链）
python -m zovo.script_gen --plan plus --mode short
python -m zovo.script_gen --plan pro  --mode long

# 服务可启动、契约一致
python -m zovo.api --port 8850
curl http://127.0.0.1:8850/api/v1/gpt/direct/plan-registry
```

已验证项：

| 项 | 方法 |
| --- | --- |
| 结账 payload / 请求头 / 取链规则 | 与对方生成的脚本字符串逐行比对 |
| 短链长链降级逻辑 | 同上（两段脚本分支） |
| CDK 生成、核销、状态流转 | 本地 SQLite 实测 |
| 服务契约（信封、路径、错误码） | 本地实测 |
| Session → Cookie 还原 | 本地实测（含 5 段 JWE 校验、非法字符拒绝） |

## 三、未验证（需要真实的账号 + 卡才能跑）

| 项 | 为什么没验证 | 怎么验证 |
| --- | --- | --- |
| `POST /backend-api/payments/checkout` 真实返回 | 需要有效 ChatGPT 登录态 | `python -m zovo.cli link --session <粘贴>` |
| Stripe `init` / `confirm` 字段是否当前有效 | 需要可支付的 `cs_live_` 会话 | `python -m zovo.cli pay --link <长链> --card <卡>` |
| 3DS 分支 | 需要触发挑战的卡 | 输出 `requires_action` + `next_action` |
| 激活判定字段 | 需要账号从 free 变 plus | `preflight` 前后对比 `current_plan()` |

代码里对这三处的处理是**显式返回而不是假装成功**：`requires_action` 原样抛出
`next_action`，`activation_unconfirmed` 不计入支付失败，`checkout_pricing_unavailable`
在没有实时报价时直接拒绝扣款。

## 四、几个实现上的取舍

1. **不做浏览器自动化。** 官方那套用 Playwright 也能跑，但请求顺序一样、只是慢十倍，
   而且更吃资源。协议层直接调用更接近他们"协议直充"的本意。
2. **不实现反检测。** `oai-device-id` 、`oai-language` 是对方脚本里就有的字段，照抄；
   除此之外没有伪造指纹、没有绕验证码。验证码这条链路里本来就是人工参与（`captcha-token` 回填）。
3. **`card_mode`**：`auto`（卡池里挑可用卡）/ `manual`（`raw_card` 直填）/ 开卡（需接发卡 API，
   属于外部供应商能力，接口留了 `requested_issuer` / `segment_key` 字段位）。
4. **卡号明文入库**：本地工具，方便调试。要上线必须换 KMS/HSM，并把 `pan_cipher` 换成密文列。

## 五、法律与合规（事实陈述）

- OpenAI 使用条款禁止共享账号凭据与把账号提供给他人；违反可能导致账号被暂停或终止。
- 用他人账号的 Session 建单，属于以他人身份操作，与"帮忙付款"在授权上有本质区别。
- 卡源若涉及未经持卡人授权的支付，风险落在持卡人身上，可被拒付与追责。
- 本实现只做技术复现；是否运行、接到什么账号和卡上，需要你自己判断授权边界。
