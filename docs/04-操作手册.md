# 04 · 操作手册（自己跑通完整链）

目标：从零把「Session → 官方结账 → 支付 → 订阅生效」这条链自己走一遍。
按顺序做，每一步都可以单独验证。

---

## 0. 前置条件

| 需要什么 | 说明 |
| --- | --- |
| ChatGPT 账号 | 用于被充值的账号，需要能正常登录 |
| 出口代理 | 建议非大陆出口。**出口国家会影响区域定价**，如果只想验证链路，用任意出口都行 |
| 一张可支付的卡 | 只在第 5 步（真实扣款）需要；第 1–4 步不需要 |
| 本机环境 | Windows + Python 3.11 + `requests`（已就绪） |

设好代理环境变量（后面所有命令都靠它出境）：

```powershell
$env:ZOVO_PROXY="http://127.0.0.1:7897"
$env:ZOVO_PAYMENT_PROXY="http://127.0.0.1:7897"
cd "./impl"
```

---

## 1. 取 Session（唯一需要人工的输入）

1. 在**已登录**的浏览器里打开：

   ```
   https://chatgpt.com/api/auth/session
   ```

2. **复制整页 JSON**（`Ctrl+A` → `Ctrl+C`）。

   > 页面上会有一段自带的警告："DO NOT SHARE ANY PART OF THE INFORMATION YOU SEE HERE"。
   > 它说的是实话——这段 JSON 等于账号密码。所以**不要发到聊天、不要提交到仓库**。

3. 存到本地文件（本目录已建好 `.secrets\`，且已加 `.gitignore`）：

   ```
   ./.secrets\session.json
   ```

4. 自检：文件里必须能看到 `"sessionToken"` 字段。
   - 有 → 可以继续。
   - 只有 `accessToken`（`eyJ` 开头三段）→ **不行**，这条路要的是 `sessionToken`（五段 JWE）。

后面命令里用 `--session "@./.secrets\session.json"` 引用它，
凭据不会出现在命令行历史或聊天记录里。

---

## 2. 验证凭据（`check`）

```powershell
python -m zovo.cli check --session "@./.secrets\session.json"
```

预期输出（示例）：

```json
{"session_keys": ["accessToken","account","expires","user"], "account": "..."}
{"plan": "free", "active_until": null, "will_renew": null, "processor": null}
```

- `plan` 是 `free` → 可以开新订阅。
- `plan` 已有值 → 说明是续费/升级场景，需要走 `pro_5x_renew` 那类 `card_attach` 流程。
- 这里就报 401/403 → Session 过期或复制不完整，回到第 1 步重取。

---

## 3. 预检 + 拿实时报价（`preflight`，不扣款）

```powershell
python -m zovo.cli preflight --session "@...\session.json" --plan plus --country PH --currency PHP
```

预期输出关键字段：

```json
{
  "account": {"email": "..."},
  "subscription": {"plan": "free", "active_until": null},
  "preflight_token": "…",
  "quotes": {
    "plus": {
      "checkout_session_id": "cs_live_xxx 或 oaic_xxx",
      "processor_entity": "openai_llc",
      "link": "https://chatgpt.com/checkout/openai_llc/cs_live_xxx",
      "currency": "PHP",
      "amount_minor": 98214
    }
  },
  "payment_path": "cs_live"
}
```

判读：

- `payment_path: cs_live` → `checkout_session_id` 以 `cs_` 开头，**能用 Stripe 接口直接付**。
- `payment_path: oaics` → 拿到的是 OpenAI 侧会话，需要走官方托管页支付（可先只验证到"能拿到链接"）。
- `amount_minor` 就是这次要扣的钱（PH Plus 档实测 ≈ 98214 分 = PHP 982.14）。
- 出错对照见第 8 节错误码表。

> 注意：这一步会在账号上创建一次结账会话（不扣款），OpenAI 侧会留记录。别反复刷。

---

## 4. 取支付链接（`link`，不扣款）

```powershell
# 短链（OpenAI 托管页，兼容性最好）
python -m zovo.cli link --session "@...\session.json" --plan plus --country PH --currency PHP

# 长链（Stripe 直付页，拿到 cs_live_ 才能程序化支付）
python -m zovo.cli link --session "@...\session.json" --plan plus --country PH --currency PHP --long
```

长链失败会自动降级短链（这就是官方的行为，输出里会写明 `[long link unavailable: ...] falling back to hosted`）。

**到这里"协议层"就验证完了**：你手上有了与官方页面完全等价的支付链接。

### 只想人工跑通（最省事）

把短链复制到浏览器打开，用卡正常支付即可。支付成功后：

```powershell
python -m zovo.cli check --session "@...\session.json"     # plan 应变成 plus
```

## 5. 程序化支付（`pay`，**这一步会真实扣款**）

前提：第 4 步拿到的是 `cs_live_...` 长链。

```powershell
python -m zovo.cli pay --link "https://checkout.stripe.com/c/pay/cs_live_xxx" `
                       --card "4111111111111111|12|30|123" `
                       --holder "John Smith" --billing-country US `
                       --address1 "350 5th Ave" --city "New York" --state NY --postal-code 10118
```

三种结果：

| 输出 | 含义 | 下一步 |
| --- | --- | --- |
| `status: paid` | 扣款成功 | 去第 6 步确认订阅 |
| `status: declined` + `decline_code` | 发卡行拒付 | 换卡；`insufficient_funds` 要先充值 |
| `status: requires_action` + `next_action` | 需要 3DS 验证 | 浏览器打开 `next_action` 里的链接人工完成 |

常见报错：

- `error.param` → Stripe 说缺哪个字段，照着补到 `stripe_pay.py` 的 `extra={...}` 里。
- `card_not_offered` → 这个会话不接受卡支付，换套餐或换地区。
- `publishable_key_not_found` → 会话已过期，回第 4 步重取链接。

### 一步到位（取链 + 支付 + 等激活）

```powershell
python -m zovo.cli topup --session "@...\session.json" --plan plus --card "4111...|12|30|123"
```

先用 `--dry-run` 演练（只取链不扣款）：

```powershell
python -m zovo.cli topup --session "@...\session.json" --plan plus --dry-run
```

## 6. 确认订阅生效

`topup` 会自动轮询；手工确认用：

```powershell
python -m zovo.cli check --session "@...\session.json"
```

- `plan` 变成 `plus` → 完整链跑通。
- 出现 `activation_unconfirmed` → 钱扣了但订阅还没翻面，等几分钟再查；**不要重复下单**。

取消自动续费（避免下一期被同一张卡扣）：

```powershell
python -m zovo.cli preflight --session "@...\session.json" --plan plus    # 确认状态
# 需要取消时在 orders.py 里调用 sess.cancel_renewal()
```

## 8. 错误码对照表

| 错误码 | 含义 | 处置 |
| --- | --- | --- |
| `gpt_session_format_invalid` | 不是 5 段 JWE / JSON 里没有 sessionToken | 重新完整复制 `/api/auth/session` |
| `gpt_session_invalid_chars` | 含中文/全角/省略号，复制被截断 | 重新完整复制 |
| `account_check_forbidden` | 凭据失效 | 重登录后重取 Session |
| `already_subscribed` | 已有同档或更高订阅 | 到期后再买，或走升级差价 |
| `store_subscription_processor` | 订阅由 App Store / Google Play 管理 | 换网页开通的账号 |
| `gpt_risk_blocked` | OpenAI 判异常活动（unusual activity） | ①先在浏览器里打开 ChatGPT → 设置 → 订阅，**手动点一次「升级」**打开套餐弹窗；②回命令行重试；③仍不行就换出口 IP（数据中心 IP 最容易被判）或换账号。同一账号 4 小时内别重复提交 |
| `checkout_rate_limited` | 结账太频繁被限流 | 等 10 分钟 |
| `checkout_pricing_unavailable` | 拿不到实时报价 | 稍后重试；**绝不在没有报价时扣款** |
| `amount_range` | 报价超出档位上限 | 检查地区/币种，防止异常价被扣 |
| `gpt_checkout_link_not_long` | 拿不到 Stripe 长链 | 用短链 |
| `bank_declined` | 发卡行拒付 | 换卡 |
| `merchant_blocked` | 在 Stripe 侧被拦，未到发卡行 | 换卡 |
| `cs_live_confirm_incomplete` | 支付未完成 | 换卡重试 |
| `requires_action` | 需要 3DS | 浏览器人工完成 |
| `activation_unconfirmed` | 已付款但订阅未确认 | 等待后复查，**不要重复下单** |

## 9. 三个"卡壳点"和它们的真实解法

### 9.0 实战记录：UI 能开单，脚本开不了（2026-10-17）

同一账号、同一浏览器、同一 IP：

| 发起方式 | 结果 |
| --- | --- |
| 点 Upgrade（官方 UI） | ✅ 成功，拿到 `oaics_...` 结账页 |
| 浏览器里跑脚本（fetch 同一接口） | ❌ `400 unusual activity` |
| 命令行 headless | ❌ `400 unusual activity` |

结论：`/backend-api/payments/checkout` 对"非 UI 发起"的请求有**独立风控**，
与 IP、Cookie、设备指纹无关（三者相同）。连续重试 7 次后，后续请求全部被拒——
**失败会累积风险分**。处置：① 停手，等 4 小时以上；② 用 UI 完成这一单；
③ 批量业务必须做"账号轮换 + 失败不重试"，不能指望单个账号稳定。

### 9.1 出口与地区不一致

`billing_details.country` 决定报价，但 OpenAI 也会参考请求来源 IP。
要稳定拿某国报价，就得从那国出境（官方站内原文："需要保证菲律宾定价请改用 ACC 菲律宾出口"）。

2. **卡头（BIN）**：不是所有卡都能过 OpenAI。要自己统计：记录每个 BIN 的成败与实扣金额
   （对方的做法见 `docs/01-机制拆解.md` 第 5 节），然后按成功率排序选卡。
3. **hCaptcha / 3DS**：结账页弹验证码时必须人工过（对方是把 sitekey 给前端由人点）。
   3DS 同理。所以"全自动"只在这两者都不触发时才成立。
