# 01 · 机制拆解（含证据）

> 所有结论都标注来源：`[bundle]` = 站点主包 `assets/index-Cll3wLFe.js` 及其懒加载 chunk；
> `[script]` = 站点自己生成的「F12 取链脚本」字符串；`[live]` = 登录后页面实际调用的只读接口返回。

---

## 1. 系统分层

```
┌──────────────┐   ①卡密/余额核销   ┌──────────────────┐
│ 下游卖家/用户 │ ────────────────► │ 卡台  │
└──────────────┘                    │ 订单状态机 + 卡池  │
                                    └────────┬─────────┘
                                             │ ②以目标账号身份建单
                                             ▼
                              ┌──────────────────────────────┐
                              │ ChatGPT 官方结账              │
                              │ POST /backend-api/payments/   │
                              │      checkout                 │
                              └──────────┬───────────────────┘
                                         │ ③支付对象（Stripe Checkout Session）
                                         ▼
                              ┌──────────────────────────────┐
                              │ Stripe                        │
                              │ init → confirm（用平台自己的卡）│
                              └──────────┬───────────────────┘
                                         │ ④支付成功事件
                                         ▼
                              ┌──────────────────────────────┐
                              │ OpenAI 把订阅记到目标账号名下    │
                              └──────────────────────────────┘
```

四条数据流互不重合：**身份**（Session → 官方服务端）、**资金**（平台卡 → Stripe → OpenAI）、
**权益**（官方订单 → 目标账号）、**服务券**（CDK，只存在于卡台自己的库里）。
这正是用户在 PDF《GPT 代充"卡密"原理拆解》里给出的模型，本次逆向确认了它成立。

---

## 2. 身份层：为什么必须是完整 Session

`[bundle]` 站内文案（zh-CN）：

> 「必须完整 Session：打开 chatgpt.com/api/auth/session 复制整段 JSON（含 sessionToken）。
>  仅贴 eyJ 开头的 Access Token 会被拒绝。」
> 「credentials: 不再支持纯 Access Token」

`[bundle]` 错误码：`gpt_session_token_required`、`gpt_session_format_invalid`、`gpt_session_invalid_chars`
（"含有中文、全角或省略号「…」等非法字符（多为复制不完整）"）。

对照组：`/gpt/session-to-cookie` 接口 `[bundle]` 只做一件事——把 `sessionToken` 还原成
浏览器会发送的 Cookie 头，服务端随后以这个身份发起请求。等价实现见
`impl/zovo/chatgpt.py: ChatGptSession.cookie_header`：

```
__Secure-next-auth.session-token=<JWE>; oai-did=<uuid4>; oai-language=en-US
```

**为什么 access token 不够**：结账会话要在账号上下文里创建，官方要求 Cookie 登录态 + 设备标识
（脚本里还要读 `oai-did` 作为 `oai-device-id` 请求头，仅短链模式需要）。access token 只够调用
普通业务接口（列会话、发消息），不足以建立结账对象。

## 3. 协议层：结账对象怎么创建

`[script]` 这是站点生成、让操作方粘贴到**用户自己已登录的 chatgpt.com 标签页**里执行的脚本，
也是全网唯一一处把真实请求原样写出来的地方：

```js
const session = await fetch('/api/auth/session', { credentials: 'include' }).then(r => r.json());
const headers = {
  Authorization: 'Bearer ' + session.accessToken,
  'Content-Type': 'application/json',
  Accept: 'application/json',
};
if (session.account?.id) headers['chatgpt-account-id'] = String(session.account.id);
// 仅短链模式追加：
// headers['oai-device-id'] = <cookie oai-did>;  headers['oai-language'] = 'en-US';

const resp = await fetch('/backend-api/payments/checkout', {
  method: 'POST', credentials: 'include', headers, body: JSON.stringify(PAYLOAD),
});
```

### 3.1 PAYLOAD（逐字段来自 `[script]` / `[bundle] Pe()`）

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `entry_point` | `all_plans_pricing_modal` / `team_workspace_purchase_modal` / **`settings_upsell`（长链）** | 长链走设置页升级入口 |
| `plan_name` | `chatgptplusplan` / `chatgptpro` / `chatgptprolite` / `chatgptteamplan` | Plus / Pro / Pro Lite / Team |
| `billing_details.country` | `PH` 等 | **决定区域定价** |
| `billing_details.currency` | `PHP` 等 | 同上 |
| `checkout_ui_mode` | `hosted`（短链）/ `custom`（长链） | 交付形态 |
| `price_interval` / `selected_cadence` | `month` | 非长链、非 Team 时带 |
| `promo_campaign` | `{promo_campaign_id:"plus-1-month", is_coupon_from_query_param:false}` | **仅 Plus** |
| `team_plan_data` | `{workspace_name, price_interval:"month", seat_quantity:5}` | 仅 Team |

### 3.2 响应与取链规则

```js
const sid = String(data.checkout_session_id ||
                   (data.checkout_session && data.checkout_session.id) ||
                   data.session_id || '').trim();
const entity = String(data.processor_entity || 'openai_llc').trim() || 'openai_llc';

// 短链（hosted）
const link = 'https://chatgpt.com/checkout/' + entity + '/' + sid;

// 长链（custom）
let raw = String(data.url || data.checkout_url || data.openai_checkout_url || '').trim();
if (raw.indexOf('https://checkout.stripe.com/') === 0) link = raw;
else if (sid.indexOf('cs_') === 0) link = 'https://checkout.stripe.com/c/pay/' + sid;
else throw new Error('这次拿不到 Stripe 长链（上游回的是 ChatGPT 会话）');   // 自动降级短链
```

**关键洞察**：`checkout_ui_mode` 改变的只是"把哪个页面给人看"。`sid` 本身在以 `cs_` 开头时
就是一个 **Stripe Checkout Session ID**——短链页面只是把它包了一层 OpenAI 的 UI。
所以对程序而言，两条路最终都指向同一个支付对象：

```
cs_live_xxx  →  Stripe /v1/payment_pages/{id}/init  →  /confirm  →  paid
```

站内错误码也印证了这点：`cs_live_confirm_incomplete`（"支付未完成，未扣款"）、
`gpt_checkout_link_not_long`（"本次拿不到免登录的支付链接…可改用需登录的短链"）。

### 3.3 风控反馈同样被建模

`[script]` 里对 `unusual activity` 有专门分支，站内对应错误码 `gpt_risk_blocked`
（"该账号被 OpenAI 判定为异常活动,未扣款，请更换账号"）。
`[live]` 成功率看板把它单列成桶：`blocked` / `account_manual_approval` / `account_cs_live` /
`precheck_external_sub` / `checkout_rate_limited`。

## 4. 定价层：区域价差是官方行为，平台只是选点

`[live]` `GET /api/v1/gpt/direct/plan-registry?product=gpt` 实际返回（2026-10-17）：

```json
"payment_regions": [
  {"country":"PH","currency":"PHP"}, {"country":"CL","currency":"CLP"},
  {"country":"EG","currency":"EGP"}, {"country":"JP","currency":"JPY"},
  {"country":"US","currency":"USD"}],
"plans": [
  {"key":"plus","funding":"bin_snapshot","flow":"direct","tier":2,
   "checkout_currency":"PHP","checkout_amount_minor":98214,
   "max_amount_minor":110000,"service_fee_usd_minor":15,"purchasable":true},
  {"key":"pro_5x",  "checkout_amount_minor":579464,  "max_amount_minor":650000},
  {"key":"pro_20x", "checkout_amount_minor":891966,  "max_amount_minor":1050000},
  {"key":"pro_5x_renew","flow":"card_attach"},   // 续费走"绑卡"而非新建结账
  {"key":"credit250","flow":"credit","funding":"fx_worst",
   "requires_active_subscription":true,"is_credit":true}]
```

`[live]` `GET /api/v1/gpt/direct/region-prices?country=PH` 每一项都带：

```json
{"currency":"PHP","amount_minor":98214,"minor_unit_exponent":2,
 "tax_mode":"exclusive","source":"collected_checkout","fetched_at":"2026-10-17T00:01:30Z"}
```

- `source: "collected_checkout"` —— 价格不是抄来的，是**每天真实建一次结账会话采集**的（对应站内
  "每日采集一次 ChatGPT 结账价格配置"）。
- `max_amount_minor` 是**报价上限**：实时代理报价超限就拦下不扣款（站内：`amount_range` "金额超限"，
  "報價異常會攔下不扣款"）。
- `tax_mode` 区分含税/未税（`inclusive` / `exclusive` / `unknown`），只影响展示与注资金额计算。

同币种汇率 `transaction_fx` 也是"最近一笔同币种成功卡交易"反算出来的
（`source:"openai_card_transaction"`，`units_per_usd ≈ 62.83`）。

## 5. 支付层：卡池、卡头、失败处置

`[live]` `GET /api/v1/card/openai-payments` 返回按 BIN 聚合的**实扣观测**：

```json
"by_product": {
  "PP-MC5378": [
    {"tier":"plus","label":"Plus","min_usd":15,"max_usd":20,"amount":15.63,"time":"2026-10-17T12:21:59Z","found":true},
    {"tier":"x5",  "min_usd":90,"max_usd":100,"amount":92.17,"time":"2026-10-17T12:01:20Z","found":true},
    {"tier":"x20", "min_usd":140,"max_usd":160,"amount":141.88,"time":"2026-10-17T12:11:21Z","found":true},
    {"tier":"x50", "min_usd":400,"max_usd":650,"amount":465.44,"time":"2026-10-17T11:33:11Z","found":true}
  ]}
```

也就是说：**哪张卡头（BIN）在 OpenAI 那里能过、实扣多少、最近什么时候过的**，是他们最核心的资产。
站内还有专门的"卡 BIN 通过率"页面。

`[live]` `GET /api/v1/gpt/direct/card-rules?product=gpt`：

```json
{"count_failures":true,"light_max_uses":5,"pro20_max_uses":3,
 "auto_switch_on_fail":false,"max_auto_switches":2,
 "select_mode":"default","strict_select":false,
 "exclude_archived_cards":true,"pro_allow_used_card":false}
```

→ 一张卡 Plus 档最多用 5 次、Pro 20x 最多 3 次、失败最多自动换 2 张、默认排除已归档卡。

失败分类（站内错误码表，节选）：

| 错误码 | 含义 | 处置 |
| --- | --- | --- |
| `bank_declined` | 发卡行拒付 | 换卡 |
| `merchant_blocked` | 在 Stripe 侧就被拦，未到发卡行 | 换卡 |
| `checkout_blocked` | 结账被风控拦截，未扣款 | 换卡 |
| `checkout_account_blocked` | ChatGPT 账号被风控 | 换账号，4 小时内不要重复提交 |
| `cs_live_confirm_incomplete` | 支付未完成 | 换卡 |
| `card_unavailable` / `card_busy_other_user` | 卡不可用/被别的任务占用 | 换卡 |
| `funding_retry_exhausted` | 开卡/充值连续 5 次失败 | 关单退冻结资金 |
| `reconciliation_unpaid_timeout` | 超时未确认到支付成功 | 关单，提示不要重复下单 |
| `activation_unconfirmed` | **已付款但尚未确认激活** | 不计入支付失败 |

## 6. hCaptcha：是"人在回路"，不是绕过

`[bundle]` 前端有一个 `RemoteCaptchaDialog`：拿到订单里的 `captcha_sitekey` / `captcha_rqdata`，
用 `https://js.hcaptcha.com/1/api.js?render=explicit` 渲染，人过了之后
`POST /api/v1/gpt/direct/orders/{id}/captcha-token {token}` 回填，服务端继续支付流程。
失败分类里 `need_hcaptcha` 被归为"平台基础设施问题"，不算支付失败。

这个设计决定了它**不适合全自动**：结账页弹验证时必须有人来点。

## 7. 交付形态：CDK / 批量 / 对外 API

- **CDK**：`GPTD-` 前缀（可自定义前缀）、面额=套餐、状态机 `unused/frozen/reserved/review/consumed/disabled`。
  兑换入口 `gptRedeem`，文案"输入 GPTD 开头的 CDK"。CDK 只是**卡台自己的一次服务券**，
  可以预生成、可以批发给下游 —— 与官方会员无关。
- **批量直充**：`/gpt/direct/batches`，前端按 100 条一组分批提交（`Aa=100`），支持暂停。
- **对外 API**：`/developer/gpt-direct`，按成功次数计费（`typeGptDirectApiHold` 预扣服务费、
  失败释放），与商城共用卡池、支付状态和对账。
- **图片/费率**：Plus 档 `service_fee_usd_minor: 15`（$0.15）；命中 `cs_live` 通道的订单另加
  `csLiveFeeHint`（站内文案："约 12% 的订单会遇到 cs_live 支付通道…每单加收服务费，仅成功开通时扣除"）。
- **风险保证金**：全账户保留 $20 可消费余额（"全帳戶僅保留一筆 20U"），用于拒付追扣。

## 8. 完整时序（复现实现对应位置）

| 步 | 动作 | 站内阶段名 | 代码位置 |
| --- | --- | --- | --- |
| 1 | 还原 Cookie，校验凭据 | `credential_check` | `chatgpt.py: load_session / me` |
| 2 | 读订阅状态，挡"已有同档" | `credential_check` | `chatgpt.py: current_plan` |
| 3 | 建结账会话 → 拿实时报价 | `pricing` / `checkout` | `chatgpt.py: create_checkout / quoted_amount` |
| 4 | 选卡 / 开卡 / 充值 | `payment` (`funding_state`) | `orders.py: _pick card` |
| 5 | Stripe init → confirm 扣款 | `payment` | `stripe_pay.py: StripeCheckoutPayer` |
| 6 | 等订阅生效 | `subscription` | `chatgpt.py: wait_for_activation` |
| 7 | 已付款未激活 → 对账 | `reconcile` | `orders.py: activation_unconfirmed` |
| 8 | 可选取消续费 | `renewal` | `chatgpt.py: cancel_renewal` |
| 9 | 核销 CDK、回写 | `completed` | `store.py: consume_cdk` |

## 9. 复现难在三处，且都不在代码里

1. **卡源**：能过 OpenAI 的 BIN + 发卡行的拒付容忍度。这是商业能力，不是技术能力。
2. **出口**：结账要求 EGRESS 与付款地区一致（站内文案："脚本从用户本机 IP 出口，区域定价按用户真实 IP 判定。
   需要保证菲律宾定价请改用 ACC 菲律宾出口"）。他们卖"家宽（静态住宅代理 IP）"产品来配套。
3. **风控对抗的耐受度**：`unusual activity`、`checkout_rate_limited`、账号侧封控都需要人工兜底和常换账号。
